## Skills Location

Skills are stored in `/Users/buddhamagnet/.claude/skills/` with two categories:
- **Local skills**: User-created skills in `/Users/buddhamagnet/.claude/skills/&lt;skill-name&gt;/`
- **Synced skills**: Official/Anthropic skills in `/Users/buddhamagnet/.claude/skills/synced/&lt;bucket-id&gt;/&lt;skill-name&gt;/`

## Core Skill Structure

Every skill requires a `SKILL.md` file with this structure:

### YAML Frontmatter (Required)
```yaml
---
name: skill-name
description: When to trigger and what it does. This is the primary triggering mechanism.
allowed-tools: Bash(pattern:*), Tool(pattern:*)  # Optional
hidden: true/false  # Optional
compatibility: dependencies  # Optional
---
```

### Markdown Body
Instructions for Claude to follow when the skill is invoked.

## Optional Supporting Files

Skills can include:
- **Additional markdown files**: Reference docs, guides, examples (e.g., `root-cause-tracing.md`, `REFERENCE.md`)
- **Scripts**: Python, TypeScript, Shell scripts in `/scripts/` subdirectory
- **Assets**: Fonts, images in `/assets/` subdirectory
- **Sub-agents**: Agent definitions in `/agents/` subdirectory
- **Eval tools**: Testing and evaluation scripts in `/eval-viewer/` subdirectory

## Metadata Files

- **`skills-lock.json`** (root level): Tracks installed skills with source, sourceType, skillPath, and computedHash
- **`manifest.json`** (synced skills): Contains skillId, name, description, source, and updatedAt for each synced skill
- **`.last-complete-round`**: Sync tracking file

## Data Storage Patterns

Skills **do not use dedicated databases or persistent storage** within their directories. They rely on:
- Configuration files in the target project/codebase
- External tools and APIs
- Claude Code's state management
- Temporary files in scratchpad directories

## Example Structures

**Simple skill** (dotfiles):
```
dotfiles/
└── SKILL.md
```

**Complex skill** (systematic-debugging):
```
systematic-debugging/
├── SKILL.md
├── condition-based-waiting.md
├── defense-in-depth.md
├── root-cause-tracing.md
├── condition-based-waiting-example.ts
└── find-polluter.sh
```

**Feature-rich skill** (skill-creator):
```
skill-creator/
├── SKILL.md
├── agents/
├── assets/
├── eval-viewer/
├── references/
├── scripts/
└── LICENSE.txt
```

Skills are purely instructional and resource bundles - they don't maintain state or databases themselves.</result>
