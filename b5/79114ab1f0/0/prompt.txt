### 1. Standard Structure of a Skill File

Every skill follows this pattern:

**YAML Frontmatter:**
```yaml
---
name: skill-name
description: Detailed description including WHAT it does AND WHEN to trigger
allowed-tools: (optional) Tool access patterns
hidden: (optional) Boolean
compatibility: (optional) Required environments/tools
license: (optional) License info
---
```

**Markdown Body:**
- Main heading (# Skill Name)
- Overview/introduction section
- Clear step-by-step instructions with ## headings
- Examples and patterns
- Optional references to bundled resources

**Directory Structure:**
```
skill-name/
├── SKILL.md (required)
├── references/ (optional - docs loaded as needed)
├── scripts/ (optional - executable code)
└── assets/ (optional - templates, files)
```

### Capture Intent

### 4. Critical Metadata Conventions

**Description field** - Most important for triggering:
- Should be "pushy" to combat undertriggering
- Include both WHAT and WHEN
- List specific user phrases and contexts
- Example: "Use this skill whenever..." followed by comprehensive triggers

**allowed-tools** examples:
- `Bash(pattern:*)` - any bash command
- `Bash(agent-browser:*)` - specific prefix
- `Read(pattern:*)`, `Write(pattern:*)`, `Edit(pattern:*)`
- `AskUserQuestion(pattern:*)`
