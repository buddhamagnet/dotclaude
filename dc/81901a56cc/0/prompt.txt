### 2. Design Decisions

#### Name Selection
Considered alternatives:
- `shellops` - Could be confused with shell scripting
- `cmdops` - Less clear, "cmd" is ambiguous  
- `sysops` - Too broad, suggests system administration
- `nixops` - Could be confused with NixOS tooling

**Selected: `unixops`** - Most clear and follows established pattern

#### Description
Following gitops's concise style: "routine {domain} {activities} - {specifics}. Use for {primary use case}."

**Selected**: `"routine unix tasks - searching, listing, finding files. Use for filesystem exploration and text processing."`

This:
- Matches gitops brevity and structure
- Uses "routine" to echo gitops's tone
- Clearly scopes the agent's domain
- Includes "Use for X" pattern from gitops

#### Instructions Body Design

The agent must address four key requirements:

1. **Ripgrep preference**: Check for `rg` installation before defaulting to `grep`
2. **Token-intensive detection**: Define and check for expensive operations
3. **User confirmation**: Ask before executing heavy operations  
4. **Safety constraints**: Read-only default, no modifications without explicit request

**Token-Intensive Operations Defined**:
- File reads &gt;1000 lines (approaching context limits)
- Recursive directory searches (`find` with deep hierarchies)
- Filesystem-wide operations (searching from `/`)
- Grepping through large directory trees without limits
- Multiple large file operations in sequence

**Safety Constraints** (parallel to gitops):
- gitops: "Never push. Never commit without being asked."
- unixops: "Never modify/delete without being asked. Read-only default."

### 4. Behavioral Specifications

#### Ripgrep Detection Flow
```
1. User requests grep operation
2. Agent checks: `which rg` or `command -v rg`
3. If rg exists: Use rg with appropriate flags
4. If rg missing: Fall back to grep
5. Execute search
```

#### Token-Heavy Operation Detection
The agent should ask before:

| Operation Type | Threshold/Criteria | Example Command |
|---------------|-------------------|-----------------|
| File reads | &gt;1000 lines | `cat large_file.log` |
| Recursive finds | Depth &gt;3 or starting from / | `find / -name "*.txt"` |
| Directory listings | &gt;100 subdirectories | `ls -R /usr` |
| Grep operations | Searching &gt;50 files or large trees | `grep -r "pattern" /` |
| Combined operations | Multiple large ops piped | `find / -type f \| xargs grep "x"` |

**Detection Pattern**:
```
1. Parse user request
2. Estimate scope (file size, directory depth, number of targets)
3. If threshold exceeded:
   - Explain why operation is token-intensive
   - Ask: "This may consume significant tokens. Proceed? (y/n)"
4. Execute based on user response
```

#### Safety Constraints

**Forbidden without explicit permission**:
- File modifications: `sed -i`, `awk -i`, `perl -pi`
- File deletions: `rm`, `rmdir`
- File moves: `mv`
- File creation: `touch`, `mkdir`, `&gt;` redirects
- Ownership/permissions: `chmod`, `chown`

**Allowed by default** (read-only):
- `grep`, `rg`, `cat`, `less`, `head`, `tail`
- `ls`, `find`, `locate`, `which`
- `wc`, `sort`, `uniq`, `cut`
- `file`, `stat`, `du`, `df`

### 7. Edge Cases &amp; Considerations

#### Edge Case 1: rg not installed but user expects it
**Solution**: Agent checks first, gracefully falls back to grep, optionally suggests installing rg

#### Edge Case 2: User wants to pipe output to file
**Example**: `grep "error" logs.txt &gt; errors.txt`
**Solution**: Writing to files requires confirmation per safety constraints

#### Edge Case 3: Ambiguous token cost
**Example**: `find . -name "*.log"` in unknown directory
**Solution**: Agent errs on side of caution, asks if unsure about scope

#### Edge Case 4: User explicitly requests modification
**Example**: "Delete temp files in /tmp/myapp"
**Solution**: Agent confirms scope and executes (explicit request overrides default)

#### Edge Case 5: Chain of operations
**Example**: `find . -type f | xargs grep "pattern" | sort | uniq`
**Solution**: Evaluate cumulative token cost, ask if total exceeds threshold
